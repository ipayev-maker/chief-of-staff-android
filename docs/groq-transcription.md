# Распознавание голосовых через Groq

Подготовлена замена платного OpenRouter STT на прямой Groq API с моделью
`whisper-large-v3`. Модель разбора текста Telegram и Gmail не меняется.

## Активация

1. Создать ключ в аккаунте Groq на Free Plan: https://console.groq.com/keys.
2. Сохранить его в Supabase Edge Function Secrets проекта
   `spabmyyxiufuzsaydrmx` как `GROQ_API_KEY`.
3. Проверить защищённую диагностику и выполнить распознавание контрольного
   голосового сообщения. Ключ не передавать в браузерный код, Git или логи.

При наличии ключа Telegram и повторный разбор в cos-notes автоматически
выбирают Groq. До добавления ключа сохраняется текущий OpenRouter STT;
это состояние явно видно в диагностике и не означает завершённый переход.
`VOICE_TRANSCRIPTION_PROVIDER=groq` позволяет принудительно выбрать Groq:
отсутствие ключа тогда даёт ошибку конфигурации, без платного fallback.
Явное значение `openrouter` служит операторским откатом.

Бесплатность определяется тарифом Groq, а не названием модели. Если ключ
принадлежит платному тарифу, запросы могут тарифицироваться. Код не включает
платный тариф и не переключается на OpenRouter при ошибке или лимите Groq.

## Поток и границы

Исходное OGG сначала сохраняется в закрытом хранилище. Сервер отправляет
сам файл в `https://api.groq.com/openai/v1/audio/transcriptions` через multipart,
с `language=ru`, `temperature=0` и JSON-ответом. Приватные URL хранилища и
URL Telegram с bot token провайдеру не передаются.

Сохраняются текущие лимиты приложения: 10 МБ и 10 минут на одно сообщение.
Таймаут распознавания — 35 секунд. Ошибки и пустой ответ сохраняются как
ограниченные коды; исходник остаётся доступен для повторной попытки.
В журнале используется идентификатор `groq/whisper-large-v3`, чтобы отличать
результат от прежней модели. Старые записи автоматически не перераспознаются.

Защищённый cron-эндпоинт `/gmail/health` возвращает в `analysis.transcription`
только `provider`, `model`, `configured` и `groq_configured`. Он не раскрывает
ключ и не отправляет аудио провайдеру.

Для проверки настоящего API защищённый POST с телом `{"voice_probe":true}`
отправляет одну встроенную синтетическую OGG-запись: «Завтра в двенадцать
встреча с Антоном». Используется тот же адаптер и параметры, что и в боте.
Проверяются слова встречи, участника, дня и времени; возвращаются только
флаги и безопасный код ошибки. Реальные сообщения, задачи, хранилище и
Telegram API не затрагиваются. Эта проверка не запускается по расписанию.
Без выбранного и настроенного Groq сетевой вызов не выполняется.

## Проверка

Тесты проверяют multipart-файл, отделение Groq-ключа от OpenRouter,
сохранение модели в журнале полного Telegram-процесса, отсутствие повторного
распознавания дубликата сообщения, ошибки и отсутствие платного fallback.
Синтетические HTTP-ответы не доказывают качество распознавания речи;
проверка настоящего аудио требует ключа и отдельного контрольного сообщения.

Документация: https://console.groq.com/docs/speech-to-text и
https://console.groq.com/docs/your-data. Zero Data Retention настраивается
в Groq Data Controls отдельно от приложения.
